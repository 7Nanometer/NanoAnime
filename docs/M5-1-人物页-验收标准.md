# M5-1 · 人物页 `/person/[id]` · 验收标准

> 2026-10-06 定稿 ｜ 拟稿：Claude Code ｜ 审定：文档区
> **用途**：实现完成后逐条跑，按 A–H 分组报结果。
> **上游**：`docs/M5-1-验收标准.md`（上半场 · 详情页三块）。

⚠️ **数据快照声明**：下方具体数字（24 行 / 19 部 / 97 部 / 8145 / 1,062,429…）都是 **2026-10-06 实测快照**。
AniList 数据随时会变，**数字不符时先核对是不是数据变了，不要当 bug 修**。

---

## 已定下的设计（实现前必读）

| 项 | 裁定 |
|---|---|
| **排序** | **人气倒序（代表作优先）**。批与批之间不保证全局有序（分页固有代价，已知晓） |
| **首屏行数** | **24 行**（与搜索页结果上限一致，不再另造数字） |
| **简介** | 默认折叠，标题写明「英文简介（来自 AniList）」；**markdown 残留必须清掉** |
| **职位标签** | 最多 3 个，超出显示「**+N**」 |
| **作品行** | 每一行可点进作品详情页（往返闭环） |
| **别名 `alternative`** | **不显示**（实测有成人向作品化名，如新房昭之的「南澤十八」） |
| **数据来源** | `staffMedia`（制作）+ `characterMedia`（配音）**两个来源合并** |
| **到底时** | 按钮**直接消失**，不加「已全部显示」（理由见 D4） |
| **职位标签口径** | **先归一化（去括号）→ 再去重 → 再截断 +N**（顺序不能换，反例见 C5） |

## A · 入口（详情页两块的人名变链接）

**A1 制作人员块人名可点**
怎么验：`/anime/16498`（进击的巨人）→「制作人员」→ 点「諫山創」
预期：进入 `/person/106705`，不是 404

**A2 声优块人名可点**
怎么验：同一页「声优」→ 点「梶裕貴」
预期：进入 `/person/95672`

**A3 链接可发现、键盘可达**
怎么验：鼠标悬停看反馈；Tab 键聚焦人名后按 Enter
预期：有 hover 反馈（下划线之类）、可聚焦、Enter 能进；**排版不因变链接而乱**

**A4 详情页原有内容不变**
怎么验：`git diff` + 页面肉眼对照改动前
预期：三块的行数、顺序、文案（含「仅列出主要制作人员，非完整名单」和底部小字）**全不变**，唯一变化是人名成了链接

**A5 人物页自己不链自己**
怎么验：`/person/106705` 点头部的名字和头像
预期：无反应 —— 不刷新、不跳 404

## B · 人物页头部

**B1 头像**
怎么验：`/person/106705`、`/person/103509`
预期：显示 AniList 头像（抽样 20/20 都有）；走 Next/Image（`s4.anilist.co` 已放行）

**B2 名字 + 罗马音**
预期：主行日文写法（諫山創 / 澤野弘之），副行罗马音（Hajime Isayama / Hiroyuki Sawano）

**B3 职位标签**
怎么验：`/person/103509`
预期：中文标签如「音乐 / 作曲家」（走现有 `staff-roles` 中文表）；没命中的原样英文；职位为空时整行不出现
⚠️ **补测【审补充】**：`primaryOccupations` 是**另一套词汇**（Director / Voice Actor / Animator / Mangaka / Music Producer…），和 `staff-roles` 表里的**职位名**不是同一批。
→ 先抽 20 人统计命中率；**命中率低就补映射表**（那张表本来就该覆盖两套词汇）；没命中的原样英文（同详情页规则）

**B4 信息行**
怎么验：`/person/103509`、`/person/118913`（千葉孝幸，实测无简介、冷门）
预期：出生年 / 自 XXXX 年活跃 / AniList 收藏数 —— **有一项显示一项，缺的那项不出现**（不是显示「—」）；三项全缺则整行不出现
※快照：澤野弘之 1980 年生、2006 年起活跃、AniList 收藏 8145

**B5 简介默认折叠**
怎么验：打开页面第一眼，然后点开、再点收起
预期：默认只看到折叠头；点开展开；再点收起。**不是一进来就铺一大段**

**B6 简介里的 markdown 残留已清掉**
怎么验：`/person/103509` 展开简介看开头
预期：开头是「Website | Website (nZk) | Twitter | …」这样的**纯文本**；**不出现 `[Wiki (jp)](https://…)` 这种方括号+网址**
※技术路径已实测：`description` 传 `asHtml: true` 返回的是**真 HTML**（`<p><a href=…>`），复用 `anilist.ts` 现成的 `parseDescription` 即可；若对人物简介无效，退到剥 markdown 语法（`[文字](链接)` → 文字）

**B7 没有简介的人**
怎么验：`/person/118913`（实测无简介）
预期：**折叠块整体不出现**（不是空框）

**B8 不显示别名**
怎么验：`/person/100089`（新房昭之）
预期：只显示主名；**不出现**「Taiji Shiiya / Juuhachigou Minamizawa（南澤十八）」等别名

**B9 页面标题**
怎么验：看浏览器标签页
预期：人物名（如「諫山創」）

**B10 人物页也有名字说明小字【审补充】**
背景：方案的页面结构里写了「❶ 人物名说明那行小字（复用 `PersonNameNote`）」，但**验收 B 组漏了它**。
怎么验：看人物页头部
预期：有一行小字，说清「这是 AniList 上的日文写法 / 复制去搜请用罗马音」—— **与详情页两块同一组件、同一措辞**
（**三处都有才一致**：制作人员块 / 声优块 / 人物页）

## C · 作品列表

**C1 声优的作品来自 `characterMedia`** —— **本轮最容易做错的一条**
怎么验：`/person/95672`（梶裕貴），**不点加载更多**
预期：第一屏出现《進撃の巨人》《鬼滅の刃》《僕のヒーローアカデミア》等**配音作品**
※依据：他 `staffMedia` 总共只有 **19 部**（几乎全是主题歌），配音作品全在 `characterMedia`（4 页 = 97 部）—— **只取 `staffMedia` 的第一屏会是一串主题歌，等于做错**

**C2 同一部作品多条边合并成一行**
怎么验：`/person/103509` 找《青の祓魔師》
预期：**只有 1 行**（实测它有 3 条登记：Music / Insert Song Composition (eps 19,25) / Insert Song Arrangement (eps 19,25)）
※更极端样本：《凸变英雄X》有 **7 条**登记 → 也是 1 行

**C3 排序 = 人气倒序**
怎么验：`/person/103509` 看第一行；再看 `/person/95672` 第一行
预期：**两者第一行都是《進撃の巨人》**（2013 · TV）※快照人气 1,062,429；澤野那行职位「音乐」，梶裕貴那行小字「配音：エレン・イェーガー」

**C4 行内容**
预期：年份 · 形式 · 标题 + 小字行；**年份缺失显示「—」**（与年表一致）；形式走现有 `getShortFormatLabel`

**C5 职位标签最多 3 个 +「+N」**
怎么验：`/person/103509` 找《俺だけレベルアップな件》
预期：「音乐 / 主题歌作曲 / 主题歌作词 **+3**」（实测该作品合并后 6 个职位）
⚠️ **口径必须写死：先归一化（去括号）→ 再去重 → 再截断 +N**。
**反例**：《ギルティクラウン》8 条登记里有 6 条归一化后是**同一个标签**，去重后只剩 2 个 —— **不去重会数成 +5，是错的**
※ 没命中中文表的**原样英文**（如「Insert Song Composition」），不硬翻 —— 与详情页同一规则

**C6 配音小字与空角色名**
怎么验：`/person/95672`；另找角色名为 null 的行
预期：「配音：エレン・イェーガー」；角色名为 null 时**不显示、不崩、不出「配音：null」**

**C7 每一行能点进作品页（往返闭环）**
怎么验：`/person/103509` 点《進撃の巨人》那一行
预期：进入 `/anime/16498`；那一页年表里 2013 那行标着「当前」

**C8 列表标题不写数字**
预期：标题是「参与作品」—— **不出现「共 N 部」**（沿用新纪律）

**C9 跨来源合并（纯函数单测）**
怎么验：造一条数据 —— 同一部作品**同时出现在 staff 和 cast 两个来源**
预期：合并成 **1 行**，职位和配音小字**都在**
※真数据可达性：`/person/95672` 的《K》《ハイスクールDxD BorN》确实同时是他的配音作品和主题歌作品，但是否落在已加载页里取决于人气序 —— **落到了必须是一行；没落到就跳过**（不作硬性预期）

## D · 加载更多

**D1 首屏 24 行 + 按钮**
怎么验：`/person/103509`
预期：24 行，末尾「加载更多」按钮（**按钮不带数字**）

**D2 点击追加、不重排**
怎么验：点一次
预期：行数增加（实测量级：每次 **+18~48 行**），原有 24 行的**顺序一行不动**，新增的追加在后面
※已知代价（已裁定接受）：加载更多后不保证全局有序 —— 两个来源各自分页、跨来源合并后，后面的行可能人气更高。**只要不重、不漏就行**

**D3 不重复**
怎么验：连点 3 次后，搜任意一部熟悉的作品
预期：同一部作品在列表里**只出现 1 次**（跨批按作品 id 去重）

**D4 到底时按钮消失**
怎么验：换一个作品少的人（如 `/person/118913`，实测 21 部）点到没有更多
预期：某批**两个来源都返回 0 条**后按钮消失
**不加「已全部显示」之类断言** —— 严格说"全部"需要限定语（"AniList 上登记的"）才准确，加限定语太长、不加又不准，**所以不加最干净**；按钮消失本身就是标准信号
※口径警告：大牌声优取 4 页仍未到底（100 条边 → 80~97 部），**拿梶裕貴验"到底"会点到手酸** —— 用小人物验

**D5 加载中与失败**
怎么验：探针把「加载更多」的请求改成失败
预期：页面不崩、已有行**一动不动**；按钮**回到可点状态**；一行小字说明这次没加载出来（可重试）

## E · 空状态与失败路径

**E1 两个来源都查不到作品**
怎么验：纯函数单测造数据（真数据 20 人最低 1 部，见 H 组）
预期：列表位置一行说明「AniList 上暂时查不到这个人参与的作品。」—— **不写数字、不写「全部」**

**E2 没有头像**
怎么验：单测 / 临时造数据（20/20 抽样都有头像，真数据无样本）
预期：灰底占位，**不破版、不出现裂图图标**

**E3 人物 id 不存在**
怎么验：打开 `/person/999999999`
预期：中文错误页，不是英文页、不是白屏
※实测行为：AniList 对不存在的 id 返回 `Staff: null` + `errors("Not Found")`

**E4 取数失败（断网 / 429）**
怎么验：探针把人物页的请求改成失败
预期：中文错误页；点「重试」能恢复（照 `/anime/[id]/error.tsx`，Next 16 用 `retry`）

**E5 手机窄屏**
怎么验：无头 Edge **320px / 390px** 打开 `/person/103509`、`/person/100089`
预期：**不横向滚动**；长职位串（含英文标签）换行不撑破容器；头像与文字并排不挤坏

## F · 成本与缓存

**F1 首屏 = 1 次请求**
怎么验：**网络层探针数"真正出网"的请求**（项目现成手法）
预期：打开 `/person/103509` 恰好 **1 次**（人物本体 + 两来源各 2 页，全在同一个请求里用别名）

**F2 缓存 24 小时**
怎么验：生产构建下第二次打开同一页
预期：第 2 次起 **0 次出网**

**F3 每次加载更多 = 1 次请求**
怎么验：探针 + 点一次按钮
预期：出网 **+1**，不超过

**F4 限流安全**
怎么验：连点 10 次
预期：无 429；真撞上了也走 D5 的失败路径，不崩
