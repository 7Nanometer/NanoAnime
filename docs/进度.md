### 追加（2026-09-29 M0-2 收工，下次动手前必读）

- [x] **`create-next-app` 拒绝中文目录名**（npm 包名只许小写字母和连字符）→ 做法：先在英文临时目录生成，再整体搬进 `NanoAnime工程/`
- [x] ⚠️ **Next.js 16 有破坏性改动**，写代码前必须先读 `NanoAnime工程/node_modules/next/dist/docs/`（工程内 `AGENTS.md` 也这么要求）。本期踩到并已确认的三条：
  - `fetch` **默认不再缓存**，必须显式开启
  - `next/image` 的 `priority` 属性**已废弃**，改用 `preload`
  - `revalidateTag()` 现在需要第二个参数
- [x] ⚠️ **AniList 是 POST 请求**，而 Next 的 `fetch` 缓存对 POST 需 `cache: 'force-cache'` 才生效（官方文档明确支持 POST）。实测 `cache: 'force-cache'` + `next: { revalidate: 3600 }` 组合有效且不冲突
- [x] **「本季」的定义已定**：按日期自动算季度，且**距下一季开播不足 21 天就提前切到下一季**（否则季末首页全是「无排期」的死格子）。已用 9 个边界日期测过，含跨年
- [x] **剧场版（MOVIE）不排除**，与其他类型一起按人气排序
- [x] **AniList 的 `pageInfo.total` 不可信**（实测恒返回 5000）→ **M1 做搜索页翻页时不能依赖它**
- [x] ⚠️ **M0-3 卡片必须做字段兜底**：实测本季前 20 部里 **3 部没有英文名**（多为剧场版）；未开播的作品**没有评分、多数没有总集数**。不做兜底会渲染出空白或 `null`。→ M0-3 已完成兜底，逻辑集中在 `lib/anime-display.ts`

### 追加（2026-09-29 M0-3 图片问题）

- [x] **图片慢的根因**：**AniList 图床 `s4.anilist.co` 国内直连慢** + **Next 图片优化器上游抓取有 7 秒硬超时**。二者叠加 → 走优化器时约一半封面被掐断返回 500
  - 实测（本机）：图床直连单张 **2~150 秒**；经优化器 **10/20 成功**，**失败的全部卡在 7.00 秒整**
  - ⚠️ 已查遍工程自带的 Next.js 16 官方文档：**没有任何配置项可以调这个 7 秒超时**
- [x] **处置**：**开发环境关掉 Next 图片优化** —— `next.config.ts` 设 `unoptimized: process.env.NODE_ENV === "development"`，让本地浏览器**直连图床**绕开 7 秒超时；**生产环境保留优化不动**
  - 依据：线上抓图是 Vercel 的服务器在干（它在国外，抓 AniList 不慢），7 秒超时不会触发；保留优化还能正常出 WebP 和响应式尺寸
  - 已实测确认：开发环境渲染出的 `<img src>` 是图床直链、不含 `/_next/image`，懒加载仍在
- [ ] ⚠️ **M1 接 Bangumi 后改用 `lain.bgm.tv` 图床解决图片问题**（Bangumi 图床国内访问快得多）
  - ⚠️ **换图床时必须连图片优化一起关**（`images.unoptimized` 改为恒为 `true`）。原因：优化器是由**部署服务器**去抓图的——Vercel 在海外，抓 AniList（海外）快，但抓 Bangumi（国内）会慢，会重新撞上 7 秒超时。**不关优化，就只是把「本地的坑」搬成「线上的坑」**
- [ ] ⚠️ **遗留**：本地直连不再返回 500，但仍受本机网络所限——实测 20 张并发有 1 张连接中断、单张耗时 2~150 秒波动极大。**真实表现要部署到 Vercel 后才能确认**
