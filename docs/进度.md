  - → 因此上一节「Bangumi 图床国内访问快得多」**是错的**，据此定的换图床方案已作废
- [x] ⚠️ **Node 自带的 fetch 默认不走代理**：只设 `HTTPS_PROXY` 没用，**必须同时设 `NODE_USE_ENV_PROXY=1`**。正确跑法（端口换成自己代理的）：

  - 实测：裸跑 → 10 秒连接超时；只设 `HTTPS_PROXY` → 同样超时；两个都设 → 200

59. （2026-10-03 M4-1 收工追加）**RLS 必须分两层验，只验一层等于没验**。「未登录读表被拒」只能证明门外的人进不来，**证明不了屋里的人出得去**。两层是独立的：**权限层**（`grant` 给 authenticated 角色）+ **行级策略**（`using (auth.uid() = user_id)`）。正确验法：
    - 建**两个**账号 A、B（一个账号验不出隔离——只有一个用户时，「只看到自己的行」和「看到所有行」表现完全一样）
    - 权限层：A 登录后 insert / select / update / delete **都通**
    - 隔离层：A 写的记录，B **读 0 行、改 0 行、删 0 行**；A 自己的数据分毫未动
    - ⚠️ **还要补一条「B 能写自己的」**——否则分不清「B 碰不到 A 的」是隔离生效，还是 B 被一刀切禁掉了
    - 更新/删除的「被拒」表现为 **HTTP 200/204 且受影响 0 行**，不是报错（策略是过滤，不是拦截）。所以要看返回的数组长度，不能只看状态码
