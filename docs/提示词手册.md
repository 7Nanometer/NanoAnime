# Claude Code 提示词手册 · NanoAnime番鉴

> 配套：`项目宪法.md`（要转成根目录 CLAUDE.md）、`产品方案.md`、`进度.md`
> 用法：找到对应阶段，整段复制到 Claude Code。

## 三条铁律

**说结果，不说步骤**
```
❌ 打开 app/page.tsx，在第 23 行加一个 fetch……
✅ 首页显示 20 部本季新番封面墙。数据用 AniList。
```

**报错贴全文**
文件名 + 行号 + 错误信息，一个字不改。总结一次，多绕一圈。

**每条都要验收标准**
缺了它就会一直问"这样可以吗"。

## 五、M2 · 日历 + 追番（10-05 ~ 10-06）

**日历**
```
做 /calendar：一周 7 列，每列列出当天播出的番剧（小封面 + 名字 + 第几集）。
今天那列要醒目。数据用 AniList airingSchedule。

注意：airingSchedule 的完整性分两种场景 —— ① 详情页查单部番会缺数据（开头几集、单次上限 25 条）；
② 日历查全站一周，实测「该更新却查不到」的 = **0 部**（查不到的是 PV/CM 合集与常青长番，它们这周真的没更新）。
兜底保留：某列一部都没有时显示「排期待定」。

验收：能看本周每天更新什么。
```

**追番 + 进度**
```
1. 详情页加「追番」按钮，可加入 / 取消
2. /my 列出追番：封面 + 名字 + 已看集数 + 每集打钩
3. 打钩记录进度

先存浏览器本地。读写逻辑抽到 lib/collection.ts，不要写死在页面里——下阶段要换云端。
长番（集数多）的列表默认定位到最近更新的集数，不要从第 1 集开始。
一部都没追时显示引导文案，不要留空白页。

打钩语义：点第 N 集 = 第 1~N 集全部打上，「已看集数」就是 N；再点当前那集取消。不做逐集独立勾选。
/my 的番剧信息（封面 / 名字 / 集数）在点「追番」时顺手存一份快照进本地，不要每次实时拉——
AniList 抖动时整页会失败，而"刷新不丢"必须真的不丢。

验收：加入追番、打钩进度，刷新都不丢。
```

## 七、M4 · 账号与云同步（10-08 起）

> **动手前必须知道的两条已核实前提（2026-10-03）**
> 1. **Supabase 国内可直连**（没被墙），但没有大陆节点，请求跨境。登录/同步这类**低频操作可接受**，别拿它做高频请求。
> 2. 🔴 **免费版内置邮件是废的**：官方限流 **每小时 2 封**，发件人是共享域名，QQ / 163 / Gmail 大概率进垃圾箱。
>    → **所以不能用「魔法链接」「邮箱验证码」「邮箱确认」这类依赖发邮件的方案。**

**你先做的（约 10 分钟，浏览器操作）：**

1. 打开 `supabase.com` → 用 **GitHub 账号**登录
2. **New project**：
   - Name：`nanoanime`
   - Database Password：**设一个强密码并存好**（管理数据库要用，丢了找不回）
   - Region：选 **Tokyo（东京）** —— 离国内最近
3. 等 1–2 分钟初始化，然后拿两样东西给 Claude Code 填进 `.env.local`：
   - **Project URL**（形如 `https://xxxx.supabase.co`）
   - **anon public key**（Project Settings → API）
4. 关掉邮箱确认：**Authentication → Sign In / Providers → Email → 关闭 "Confirm email"**

⚠️ **要分清两个 key**：`anon` key 是**设计成公开的**（配合 RLS 使用），可以进前端；`service_role` key 是**真密钥**，**绝不能进代码或 git**。

#### Vercel 环境变量（线上登录的前提，5 分钟）

**值从哪来**：本地 `NanoAnime工程/.env.local` 里就有那两行 —— **让 Claude Code 原样贴给你复制**即可（不靠手抄，避免拼错）。
这两个值本来就公开：`NEXT_PUBLIC_` 开头的变量会被**烤进前端 JS**。

**步骤：**

1. `vercel.com` → 进 `nanoanime` 项目 → 顶部 **Settings** → 左侧 **Environment Variables**
2. **Add New**，填第一条 → **Save**：

| 栏 | 填什么 |
|---|---|
| Key | `NEXT_PUBLIC_SUPABASE_URL` |
| Value | `https://jfcryweekywhjzivczho.supabase.co`（以 `.env.local` 里的为准） |
| Environments | 勾 **Production**（Preview / Development 也一并勾上） |

3. **Add New** 第二条 → **Save**：

| 栏 | 填什么 |
|---|---|
| Key | `NEXT_PUBLIC_SUPABASE_ANON_KEY` |
| Value | 那个 `sb_publishable_...` 的**完整值** |
| Environments | 同上 |

4. **重新部署**：顶部 **Deployments** → 最新那条右侧 `...` → **Redeploy** → 确认

⚠️ **三个坑：**
- **Key 名字一字不差**（大小写、下划线）—— 代码就按这个名字读
- **Value 不要带引号、不要带前后空格** —— 从 `.env.local` 复制时最容易把引号一起带进来
- **必须 Redeploy** —— `NEXT_PUBLIC_` 是构建时烤进 JS 的，不重新构建不生效

**验收**：线上打开 `/login`，注册一个账号能直接登录。
（更硬的验法：扫线上 JS 文件里有没有 supabase 地址 —— 配好了应该扫得到；这个方法 Claude Code 已经用过一次）

**M4-1 · 登录跑通**
```
做账号系统的最小闭环：能注册、能登录、登录后服务端能读到当前用户。

停，改动太多了。
回到上一个能跑的状态，只做一件事：____
```

先读 docs/进度.md，告诉我：上次做到哪、今天下一步是什么、有无遗留问题。

## 十、卡住时

| 症状 | 对策 |
|---|---|
| 越改越乱 | `/clear` 重开，重说需求（CLAUDE.md 会自动加载） |
| 同一个错改三遍 | 贴全文 + 「先只解释原因，不要写代码」 |
| 不守约定 | `/memory` 把具体规则加进 CLAUDE.md（"2 空格缩进"优于"注意格式"） |
| 一直问你 A 还是 B | 缺验收标准，补「做完我要能……」 |
| 想装一堆依赖 | 「不新增依赖，用现有的做到能跑」 |
| 越来越慢 | 对话太长，`/clear` 后先让它读 `docs/进度.md` |

跑偏时不要重述需求，**只指出错在哪**：
```
❌（从头再讲一遍）
✅ 这改动了公共接口，保持签名不变，只改内部实现。
```
