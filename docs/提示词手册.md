# Claude Code 提示词手册 · NanoAnime番鉴

> 配套：`项目宪法.md`（要转成根目录 CLAUDE.md）、`产品方案.md`、`进度.md`
> 用法：找到对应阶段，整段复制到 Claude Code。

## 三条铁律

**说结果，不说步骤**
```
❌ 打开 app/page.tsx，在第 23 行加一个 fetch……
✅ 首页显示 20 部本季新番封面墙。数据用 AniList。
```

**报错贴全文**
文件名 + 行号 + 错误信息，一个字不改。总结一次，多绕一圈。

**每条都要验收标准**
缺了它就会一直问"这样可以吗"。

## 五、M2 · 日历 + 追番（10-05 ~ 10-06）

**日历**
```
做 /calendar：一周 7 列，每列列出当天播出的番剧（小封面 + 名字 + 第几集）。
今天那列要醒目。数据用 AniList airingSchedule。

注意：airingSchedule 的完整性分两种场景 —— ① 详情页查单部番会缺数据（开头几集、单次上限 25 条）；
② 日历查全站一周，实测「该更新却查不到」的 = **0 部**（查不到的是 PV/CM 合集与常青长番，它们这周真的没更新）。
兜底保留：某列一部都没有时显示「排期待定」。

验收：能看本周每天更新什么。
```

**追番 + 进度**
```
1. 详情页加「追番」按钮，可加入 / 取消
2. /my 列出追番：封面 + 名字 + 已看集数 + 每集打钩
3. 打钩记录进度

先存浏览器本地。读写逻辑抽到 lib/collection.ts，不要写死在页面里——下阶段要换云端。
长番（集数多）的列表默认定位到最近更新的集数，不要从第 1 集开始。
一部都没追时显示引导文案，不要留空白页。

打钩语义：点第 N 集 = 第 1~N 集全部打上，「已看集数」就是 N；再点当前那集取消。不做逐集独立勾选。
/my 的番剧信息（封面 / 名字 / 集数）在点「追番」时顺手存一份快照进本地，不要每次实时拉——
AniList 抖动时整页会失败，而"刷新不丢"必须真的不丢。

验收：加入追番、打钩进度，刷新都不丢。
```

## 七、M4 · 账号与云同步（10-08 起）

> **动手前必须知道的两条已核实前提（2026-10-03）**
> 1. **Supabase 国内可直连**（没被墙），但没有大陆节点，请求跨境。登录/同步这类**低频操作可接受**，别拿它做高频请求。
> 2. 🔴 **免费版内置邮件是废的**：官方限流 **每小时 2 封**，发件人是共享域名，QQ / 163 / Gmail 大概率进垃圾箱。
>    → **所以不能用「魔法链接」「邮箱验证码」「邮箱确认」这类依赖发邮件的方案。**

**你先做的（约 10 分钟，浏览器操作）：**

1. 打开 `supabase.com` → 用 **GitHub 账号**登录
2. **New project**：
   - Name：`nanoanime`
   - Database Password：**设一个强密码并存好**（管理数据库要用，丢了找不回）
   - Region：选 **Tokyo（东京）** —— 离国内最近
3. 等 1–2 分钟初始化，然后拿两样东西给 Claude Code 填进 `.env.local`：
   - **Project URL**（形如 `https://xxxx.supabase.co`）
   - **anon public key**（Project Settings → API）
4. 关掉邮箱确认：**Authentication → Sign In / Providers → Email → 关闭 "Confirm email"**

⚠️ **要分清两个 key**：`anon` key 是**设计成公开的**（配合 RLS 使用），可以进前端；`service_role` key 是**真密钥**，**绝不能进代码或 git**。

#### Vercel 环境变量（线上登录的前提，5 分钟）

**值从哪来**：本地 `NanoAnime工程/.env.local` 里就有那两行 —— **让 Claude Code 原样贴给你复制**即可（不靠手抄，避免拼错）。
这两个值本来就公开：`NEXT_PUBLIC_` 开头的变量会被**烤进前端 JS**。

**步骤：**

1. `vercel.com` → 进 `nanoanime` 项目 → 顶部 **Settings** → 左侧 **Environment Variables**
2. **Add New**，填第一条 → **Save**：

| 栏 | 填什么 |
|---|---|
| Key | `NEXT_PUBLIC_SUPABASE_URL` |
| Value | `https://jfcryweekywhjzivczho.supabase.co`（以 `.env.local` 里的为准） |
| Environments | 勾 **Production**（Preview / Development 也一并勾上） |

3. **Add New** 第二条 → **Save**：

| 栏 | 填什么 |
|---|---|
| Key | `NEXT_PUBLIC_SUPABASE_ANON_KEY` |
| Value | 那个 `sb_publishable_...` 的**完整值** |
| Environments | 同上 |

4. **重新部署**：顶部 **Deployments** → 最新那条右侧 `...` → **Redeploy** → 确认

⚠️ **三个坑：**
- **Key 名字一字不差**（大小写、下划线）—— 代码就按这个名字读
- **Value 不要带引号、不要带前后空格** —— 从 `.env.local` 复制时最容易把引号一起带进来
- **必须 Redeploy** —— `NEXT_PUBLIC_` 是构建时烤进 JS 的，不重新构建不生效

**验收**：线上打开 `/login`，注册一个账号能直接登录。
（更硬的验法：扫线上 JS 文件里有没有 supabase 地址 —— 配好了应该扫得到；这个方法 Claude Code 已经用过一次）

**M4-1 · 登录跑通**
```
做账号系统的最小闭环：能注册、能登录、登录后服务端能读到当前用户。
```

**🔑 B3 补测的价值当场兑现**：32 人抽样出 **13 种** `primaryOccupations`，而原 `ROLE_LABELS` **只覆盖 1 种**（Director）→ 已单开一张职业表，**13/13 全命中**。**文档区上轮那条补充直接命中。**

**三件要处理的事**：
1. 🔴 **「全重复批次」这条路径没验** —— F3 原来只在**正常批次**下验过。要清三件事：**① 那 5 次是"同一请求内的别名批次"（F3 的 +1 仍成立）还是"最多 5 轮出网"（F3 数字要改）？② 5 有实测依据吗（别重蹈「上限 4 拍脑袋」那一课）？③ 5 批全重复后停止时用户看到什么（按钮要回到可点 + 一行说明，不能"点了没反应"）**
2. **C4（缺年份显示「—」）只有代码路径、无实测样本** → 照 E1 / E2 的做法用单测造数据验
3. 🔧 **探针污染那条纪律我上轮写漏了一半** → 正确做法是**删磁盘缓存 ＋ 重启，两个都要做**。它这次是"只重启没删磁盘" → 缓存命中 → 请求根本没出网 → 探针拦不到（白测两次）。已修正验收文件

**它两个失误都自己串上了**：
- **测试脚本两次假失败** —— `a.click()` 读到"没跳转"（换真实 CDP 鼠标事件才跳）；坐标点按钮但它在 24 行长列表下面、**超出视口点不到**（换 DOM click）→ 它自己接到 **M4-1 那条"观测手段本身要先被证明有效"**
- **探针污染骗了它两次** → 修正后记进纪律

**如实说明值得记**：C4 它主动写「样本 96 行里没出现缺年份的行，**这条只有代码路径没有实测样本**」—— **不把"没验到"说成"验过了"**。

**13. 三问三答已结案 —— 它删掉了循环，而不是调参**

| 问题 | 答案 |
|---|---|
| 那 5 次是什么？ | **「最多 5 轮出网」**（每次循环都打一回 API）→ F3 的 +1 在那条路上不成立 → **这个设计本身就不对** |
| 5 有实测依据吗？ | **没有，就是拍脑袋的**。补测 3 人共 **16 批**：全重复只出现 **1 次**，而且**就是"到头了"那一批**（同批 `done=true`）→ **补拉循环几乎没有存在意义** |
| 改成什么？ | **把循环整个删掉**（不补拉、也不换个数字接着拍脑袋）→ **1 次点击恒等于 1 次出网**，F3 恢复硬保证 |

**新行为**：「这一批没有新增、但还没到头」→ 一行说明「**这一批没有新的作品（都是上面已列出的），可以再点一次继续。**」+ 按钮保持可点 —— **既不"点了没反应"，也不替用户偷偷多花请求**。

**🔑 一处抽象收获（同一个项目里的两次对照）**：

| 情形 | 处理 | 为什么 |
|---|---|---|
| 年表**补抓轮数上限 4** | **调参**（→ 8） | 机制**有必要** —— 链式系列真的要多轮（进击 **7 轮**）→ 只是**数值定错了** |
| 「加载更多」**补拉循环 5 次** | **删除** | 补测显示**机制几乎不触发**（16 批 1 次、且是到头那批）→ **机制本身没必要** |

→ 🔑 **判据：一个"拍脑袋的数字"被质疑时，先问这个机制有没有被数据证明的必要 —— 有就调参，没有就删掉。**
→ 它这次**没选"改成 8 / 10"**，是对的。

**C4 已补验**：探针造「缺年份 + 缺形式」→ 实测 `— · — · 缺年份缺形式的作品 · 音乐`，两个「—」都出来 ✅

> ⚠️ **三个连带事实**：
> 1. **云端数据先导出存档**、数据库的表与权限**一律不动**（`0003` 迁移从未生效，库里还是原样）
> 2. **页脚与 `/login` 的文案要改回「仅你可见」** —— 那一版是对的；为公开而改的那版现在不成立了

**两个前置问题已定（2026-10-06，本人裁定）**：
1. **朋友之间互相可见** → 选 **「都公开（像 Bangumi）」** → **RLS 要放开读权限**（现在是"只看自己的行"，已两账号交叉实测）
2. **日志进系统的方式** → 选 **「App 里做后台编辑页」**（不是往仓库放 Markdown）

⚠️ **"都公开"带动一个必须先说清的隐私问题**：
- `collection` 表里有 `note` / `score` / `is_favorite` / `status` 四个字段，**目前全是空的**（本地 `lib/collection.ts` 没有这些字段，也没有写它们的 UI）→ **现在不存在泄露**
- **但将来一旦加了"备注"类 UI，它会随表一起公开** → 那时要么在界面上写明「备注公开可见」，要么把该字段排除出公开范围
- **"公开"的确切范围要定**：所有登录用户可读？还是未登录访客也能读？（追番记录在 Bangumi 上本就公开，性质上不敏感）

**拆三步（每步单独验收）**：

|---|---|---|
| **M5-2-1** | **公开可见性（RLS 改动）+ `profile` 表（handle）+ 他人主页 `/u/[name]`** | 🔴 **安全相关改动** → **动手前先出方案**（谁可读 / handle 怎么定 / 那四个字段怎么办） |

| **M5-2-3** | **图片上传**（Supabase Storage） | 动漫解析必须有图，但不能省掉前两步 |

**两处结构性提醒**：
- **`/my` 与他主页必须分开**：`/my` 是**管理页**（有打钩、取消追番等**写操作**），`/u/[name]` 是**只读展示页**。合并会让"别人能点你的打勾"这类问题出现
- **RLS 改动必须三态验证**（照宪法第 13 条那条纪律）：① **未登录访客只能读、不能写**；② **A 能读 B 的**；③ **A 不能改 B 的**（只能改自己的）—— **②③ 缺一不可**，只验 ② 会漏掉"误放写权限"

#### M5-2-1 方案已审（2026-10-06）—— 五处全按它的推荐 + 三条补充

**它第 0 节的基线实测值得学**：直接打线上 Supabase 的 REST 接口（**就是 anon key 明晃晃挂在浏览器里时、别人能打到的那个门**），未登录 / 用户 A / 用户 B 三种身份各测一轮。结果：未登录**四条全 401**（挡在**权限层**，是结构性关死，不是策略层过滤）；A 读整表只回自己 1 行；A 冒充 B 插行 **403**；A 改/删 B 的行 **200 + 0 行（静默，不是报错）**；A 改自己成功。

**五处裁定（全部按推荐）**：

| 问题 | 裁定 | 关键理由 |
|---|---|---|
| Q1 读的范围 | **甲 · 所有人可读（含未登录）** | **乙几乎不提供额外保护** —— 注册接口是公开的（邮箱确认关着），任何人 10 秒建个号就能看，**白增一层摩擦** |
| Q2 `note` | **甲 · 结构性排除**（列级收回读权限） | 靠界面提醒不靠谱（将来做备注 UI 的人可能忘写那行字）→ **"防护要结构性、不能靠规则"** 的再次应用 |
| Q3 handle | **甲 · 用户名 URL** | 乙不省事：没法念、没法记，且想显示用户名还得建 `profile` 表 |
| Q4 设置入口 | **甲 · 只放 `/my`** | 注册页加必填字段与「登录不是使用的前提」相冲；且老账号救不回来 |
| Q5 拉取双保险 | **加** | 读放开后"看不见别人的行"只剩代码那一句 `.eq("user_id", 我)` → **手滑删了会让别人的行混进本地、还被推回云端（静默且传染）** |

**🔴 文档区补充一：一处已经开始说假话的文案（必须改）**

> 页脚那句（M4-2 刚加的）：**「未登录时只存在本机；登录后会同步到你的账号，仅你可见。」**

**读权限一放开，"仅你可见"就成了假话。** 这是**同一句话第二次因功能变化而失效**（第一次就是 M4-2 那次隐私声明）。
- **页脚**：「仅你可见」→ 改成如实说法（登录后同步到云端，**且对所有人可见**）
- **`/login` 上那句**也要更新 —— 现在只说"同步到你的账号"，**没说"对所有人可见"**
- ⚠️ **知情同意的时机也错了**：不是"设置主页时"，而是**首次同步前** —— **同步那一刻数据就公开了，跟有没有设置主页无关**

**🔧 补充二：Q2 的实现坑要提前钉住**

**列级权限下，任何 `select *` 都会失败** → **所有读取必须显式列出列名**。这就是它说的"接口层的细节"，提前钉住，别到实测才发现。

**补充三：`/u` 页面的两件事**

1. **加一行小字「仅显示已同步到云端的记录」** —— 否则访客会疑惑"他怎么只追了 3 部"（本机记录未同步）
2. **加缓存（ISR / revalidate）**，别每次实时读 Supabase —— **国内读它慢**，而这是**公开页、会被反复访问**
