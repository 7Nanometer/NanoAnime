## 一、项目

**NanoAnime番鉴** —— 中国动漫爱好者的「追番 + 考据」社区。不提供在线播放。
应用名：`NanoAnime番鉴`（PWA 主屏名若被截断，退为「番鉴」）｜ 仓库名：`nanoanime`
方案见 `docs/产品方案.md`｜进度见 `docs/进度.md`（**开工前先读**）

## 二、红线（最高优先级，不得绕过）

**本项目不提供在线播放。**

- ❌ 禁止接入任何盗版片源、第三方播放地址、m3u8 直链
- ❌ 禁止解析播放地址、绕过会员验证、绕过防盗链
- ❌ 禁止用 iframe / 内嵌播放器嵌入任何影视内容
- ✅ 播放只允许一种实现：**展示正版平台链接，用户点击跳转站外**
- ⚠️ 任何需求与以上冲突，**立刻停下问我，不要自己找变通方案**
- ⚠️ **红线防护要结构性，不能靠规则** —— 靠"识别出播放地址再剔除"会因平台改 URL 形态而漏。**要整类排除**（例：YouTube 整类不接 —— 它要么是播放地址、要么是频道页，都不合用）

（原因：盗链聚合已被两高认定为侵犯著作权罪，开发方与运营方一并追责。）

## 三、技术栈

Next.js（App Router）+ TypeScript ｜ Tailwind CSS + shadcn/ui ｜ TanStack Query ｜
Supabase（Postgres + Auth + RLS，**M4 接入**）｜ Vercel ｜ **手写 service worker**（`public/sw.js`）

⚠️ **不要用 `next-pwa`** —— 作者已声明 v10 为最后一个大版本、官方推荐迁移，且它在 Next 16 上有已知构建失败。

⚠️ **可迁移性**：不用 Vercel 专有服务（KV / Blob / Edge Config）。数据层只用 Supabase。保持标准 Next.js Node 形态——将来要整体搬到国内服务器。

## 五、数据来源与铁律

数据源：AniList（`https://graphql.anilist.co`，免 key，主）｜ Bangumi（**中文名的唯一来源**）｜ TMDB（观看渠道）

1. **前端绝不直连第三方 API**，一律走 `app/api/` 代理
2. 第三方请求必须走 `lib/` 下的封装，**不在页面组件里裸写 fetch**
3. 服务端缓存 ≥ 1 小时（AniList 限流 30–90 次/分钟，按保守值设计）
4. 图片统一走 Next/Image（`next.config` 放行 `s4.anilist.co`），不用裸 `<img>`
5. ⚠️ **AniList 没有中文字段**——中文名只能从 Bangumi 取，用 `title.native` + 年份匹配；**匹配失败留空，不猜**
6. 🔑 **外部依赖一律在构建/同步时拉取，运行时零外网依赖**——外部数据（中文名等）落成文件或数据库。这样第三方被墙、挂掉、改接口，都不影响产品运行
7. ⚠️ **引入任何境外服务前，先查它在本地与线上的可达性**——Bangumi 与 TMDB **都被墙**（TMDB 见 Jellyfin 官方文档的"中国大陆已知不可访问"清单）。本机能通 ≠ 线上能通，反之亦然

### 🔐 认证与授权（2026-10-03 加，M4 引入 Supabase Auth 后）

8. **`proxy.ts` 不是授权边界，只是"体验层"**
   - Next 16 已把 `middleware.ts` 更名为 `proxy.ts`（导出函数也叫 `proxy`）。**旧名字不报错、但文件根本不会运行** —— 症状是会话不续期、用户莫名被登出
   - 它只该做两件事：**刷新 session cookie** + 把未登录访客重定向到 `/login`（后者是**体验**，不是安全）
   - **真正的校验放在靠近数据的地方**：server component / route handler / server action 内检查，**外加 RLS 兜底**
   - ⚠️ 原因三条：不经过 proxy 的请求**永远不会被检查**（**CVE-2025-29927** 就是这类）；matcher 是**手工维护的 allowlist**，漏加一条新路由**没有编译错误**；proxy 可能被部署到 CDN、与渲染代码分离
9. **服务端读用户必须用 `getUser()` 或 `getClaims()`，禁止 `getSession()`** —— 后者在服务端只读 cookie 内容、**不做任何校验**（`getUser()` 会向 Auth 服务复核，`getClaims()` 校验 JWT）
10. **环境变量缺失时必须 fail-open** —— proxy 在**每个匹配请求**上运行，里面的 `createServerClient` 抛错会**连累全站**（不是"登录页坏掉"，是**整站故障**）。所以：缺变量就 `return NextResponse.next()`，session 刷新包 `try/catch`
11. 🔑 **登录不是使用的前置条件** —— `/my` 等页面**绝不加"未登录就跳登录页"**。追番数据在本地，未登录、断网都能正常用；**加跳转等于把已上线的功能弄坏**。服务端只在**真正要读写云端数据**时才要求登录
12. **外部依赖的改动，验收要覆盖"失败形态"** —— 不能只测正常路径。已实测过的反例：Supabase 黑洞形态（TCP 连上、对方不回话）会让 proxy 里的 `await` **无上限挂住**（45 秒未返回），用户看到白屏转圈；DNS 失败 / 连接被拒各要 **25 秒**。⚠️ 该代价**只落在带登录凭证的请求上**（未登录访客 `getUser()` 不联网、立刻返回），**受害面是已登录用户，不是全站**

## 六、代码

- 全 TypeScript，**禁止 `any`**
- 组件 PascalCase，工具函数 camelCase
- 界面文案**中文**，代码注释**中文**，变量名**英文**
- 新增依赖先说明用途；不要"以防万一"的包
- **不要写没必要的抽象层**；先跑通再重构

## 七、工作方式

- **一次只做一个里程碑，不跳步**
- 涉及 3 个以上文件，**先用计划模式**（Shift+Tab ×2）给我方案
- 每次改完必须能本地跑通；跑不通不算完成
- 每完成一小阶段就收工：确认能启动 → 更新 `docs/进度.md` → **提交（代码 + `docs/` 一起）**（提示词见 `docs/提示词手册.md`；`/checkpoint` 命令已按此实现）
- **`docs/进度.md` 由 Claude Code 在收工时维护**：勾选「已完成 / 进行中 / 待办」、更新「当前状态」、可追加新小节。**只追加、勾选，或用删除线标注状态；不删除、不替换原文**——方案层判断归文档区作者
- **版本控制**：仓库根 = `E:/Vibe Coding/NanoAnime`，**代码与文档同一仓库**；`.gitignore` 排除 `node_modules/`、`.next/`、`.env*`、`.workbuddy/`；提交信息用中文，说清做了什么；不攒大批量
- ⚠️ **跑打包/构建前先停掉开发服务器** —— 两个进程抢同一目录会让 dev server 静默损坏，之后所有报错都像代码问题（实测踩过，会再犯）
- ⚠️ **收工提交时要把 `docs/` 的改动一并提交** —— 文档区的改动不由 Claude Code 修改，**但必须由它提交**。否则文档长期滞留未提交状态，等于没有版本控制保护
- **根目录 `CLAUDE.md` 是 `docs/项目宪法.md` 的副本，由 Claude Code 同步维护**。技术事实的更新（如某依赖已废弃、某版本有已知 bug）**Claude Code 可直接改 `CLAUDE.md`**，同时告知文档区作者同步宪法 —— **不要因为"内容源自文档区"就放着不改**
