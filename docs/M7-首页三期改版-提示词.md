### G1 评分来源（口径见 D3）

新建 `scripts/fetch-ratings.ts`，**照 `scripts/fetch-title-zh.ts` 模板写**（离线跑 + 落文件 + 断点续跑 + 只增不减）。输出 `data/ratings.json`：

```ts
interface RatingEntry {
  anilist: number | null;    // AniList averageScore，已经是 0~100
  bangumi: number | null;    // Bangumi rating.score（10 分制）× 10 → 0~100
  anitrendz: number | null;  // 拿不到就留 null，不要凑
}
type RatingsFile = Record<string /* anilistId */, RatingEntry>;
```

- **AniList**：`averageScore`（0~100），可在集合脚本里一并带上，免多一次出网。
- **Bangumi**：用 `data/title-zh.json` 已有的 `bangumi_id` → 请求 `https://api.bgm.tv/v0/subjects/{id}` 的 `rating.score`（10 分制）→ **×10** 归一 100 制。⚠️ AniList 评分老番齐全、新番严重缺失（实测当季前 50 部只 28 部有分）→ 高分合集**跨季度取全年代榜**。
- **AniTrendz**：⚠️ **无稳定 API，要抓网页**。**先花 10 分钟探测**（`https://www.anitrendz.net/charts/`）能否稳定解析「番剧名 → 分数」：能 → 接上；不能 → 字段全留 `null` **并继续往下做**。**别卡整轮，更不许拿别处数据凑。**
- **合成**：各自归一 100 制，**只在有分来源间等权平均**；只有一个来源就**直接用那个**；**缺分不硬凑**（不用 0 分填、不用站外均值填）。
- ⚠️ **跑前实测两件事**：① 本机能否连通 `api.bgm.tv` —— 进度文档记过它 **DNS 被污染到 `199.16.156.7`**、挂代理也不通，**先本地确认能跑**；② 命令必须带代理环境变量（Node 自带 fetch **默认不读**系统代理）：`NODE_USE_ENV_PROXY=1 HTTPS_PROXY=http://127.0.0.1:7897 npm run fetch-ratings`。**Bangumi 跑不通就如实报告、只用 AniList 往下走**，不许编数据。
- `package.json` 加 `"fetch-ratings": "node scripts/fetch-ratings.ts"`。中文名/简介同批落盘、Bangumi 上仍是日文原文的如实标注——既有纪律照旧。

### G2 系列聚合（离线）

新建 `scripts/build-collections.ts` → 输出 `data/collections.json`。

- **种子**：`fetchPopularAnime({ sort: "SCORE_DESC" })` 翻页取**前 200 部**。⚠️ **AniList 三个实测陷阱（2026-10-06 实测，有响应头为证）**：① **`perPage` 静默截断**——要 50/100 都只回 **25** 条，不报错；② **`pageInfo.total` 彻底不可信**，同一查询翻不同页给不同总数 → **翻页一律以「这一页返回 0 条」为终止条件**；③ **限流 30 次/分钟**（响应头 `x-ratelimit-limit: 30`）→ 翻页间 sleep ≥ 2 秒。
- **串图**：`fetchMediaRelations` + `lib/series-graph.ts` 白名单（`SERIES_RELATION_TYPES` 六种，**一个都不能多**，且对面必须 `ANIME`）。反复「`nextIdsToFetch` → 抓 → 再 explore」直到无新 id。
- **输出结构**（建议）：

```ts
interface Collection {
  key: string;               // 稳定标识（用最小成员 id 即可，保证每次重算得到同一个 key）
  name: string;              // 合集名 = 代表作品的显示名（getPrimaryTitle）
  startYear: number | null;  // 代表作品的年份
  count: number;             // 成员数
  score: number;             // 合集均分：成员综合分的算术平均，**只对有分的成员求平均**
  scoredCount: number;       // 有分的成员数（用来说明这个均分可不可信）
  sources: string[];         // 这条合集实际用到的评分来源，如 ["AniList","Bangumi"]
  representative: Anime;     // 全集代表作品（综合分最高的那部），卡片直接渲染它
}
```

- ⚠️ **铁律 6：运行时零外网依赖**。卡片要显示的一切（代表作品的完整 `Anime` 字段 + 封面 URL + 中文名 + 年份 + 均分）**直接写进 `collections.json`**，运行时**只读文件**，**不要**在页面里再走 `fetchAnimeByIds`。
- ⚠️ 该文件是**重算**（非"只增不减"），但须保证**同一输入产出同一输出**（稳定排序，见 G3）。
- `package.json` 加 `"build-collections": "node scripts/build-collections.ts"`。

### G3 排序与 21 个卡片位（口径 D5 / D6）

- **卡片位 = 先聚合合集 → 排序 → 取前 21 个合集**（**不是**「取前 21 部作品再聚合」）。主排序：**合集均分降序**。
- ⚠️ **已知偏差**（我用真数据跑过探针）：一部 91 分的孤独神作均分就是 91；8 部作品的系列被其中较弱两部拉低 → **`count===1` 系统性赢**（实测：种子 100 部时按均分排序前 10 名里 **6 个**是 size=1）。
- 故定下**确定性规则**（照做，别再问）：① 先只收 `count >= 2` 的合集，按均分降序；② 不足 21 个时用 `count === 1` 的单部按分数降序**补齐**，且这类卡片**不显示「共 N 部」徽标**（`count < 2` 就不渲染）；③ 同分次序：`count` 大者先 → 再同分 `scoredCount` 大者先 → 再同按代表作品 id 升序（**保证每次重算一致**）。
- 实测参照（种子 100 部）：串图后池子 250 部、连通分量 54 个、size=1 有 14 个。种子扩到 200 部后 `count>=2` 的合集**大概率够 21 个**——**报实际数**。

### G4 卡片组件（⚠️ 不许新建第二套卡片）

铁律：`components/AnimeCard.tsx` 是**全站唯一卡片组件**，头部注释已写明「不要再建第二套」。**不要新建 `CollectionCard`**——加**一个**可选属性即可：

```ts
/**
 * 合集卡片。有值时：
 *   ① 右上角评分药丸显示**合集均分**（不是这部自己的分）
 *   ② 封面底部**不显示时间条**，改显示「共 N 部」徽标（仅 count >= 2 时显示）
 *   ③ 名字下方那一行显示「{起始年份} · 评分 {合集均分}」（而不是光秃秃的年份）
 */
collection?: { count: number; score: number };
```

- **卡片三行**（照参考截图 3）：① 封面 —— 右上角药丸 = 合集均分；封面底部徽标 = 「共 N 部」（`count >= 2` 才显示，带内联 SVG 图标）；② 合集名 —— **仍两行固定高**（`min-h-[2.6em]`），否则一行/两行混排把下面的行挤歪；③ `{起始年份} · 评分 {合集均分}` —— ⚠️ **不是**「{年份} · {N.N} 万播放」。
- **卡片代表谁（D4）**：合集内**综合分最高**那部——封面、名字、年份都取它。
- **组件** `components/HighScoreCollections.tsx`：`<h2>`「高分合集」+ 副标题「全年代 · 同系列多部组合，按合集均分排序 · 评分来源：{实际用到的那几个}」。⚠️ 副标题**必须如实写实际来源**（如「AniList · Bangumi」）；**只有一个来源时不许写「综合」**，也不许写「全网综合」；**没有分的不显示成 0 分**。21 张三行 × 7：`grid grid-cols-2 gap-x-4 gap-y-6 sm:grid-cols-3 md:grid-cols-4 lg:grid-cols-5 xl:grid-cols-7`。三态：加载 / 失败（人话 + 重试）/ 空。
- **数据通路**：服务端读 `data/collections.json`（`lib/` 下写只读文件封装，照 `lib/bangumi-index.ts` 的做法）→ 传给客户端组件。⚠️ **前端绝不直连 AniList。**
